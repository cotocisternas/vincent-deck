# Install, migrate, and roll back

Run commands from the repository root. The installer targets Linux x86-64 and
`~/.config/opendeck/`. Profile tooling is specific to device `sd-EL31L1A08599`:
eight keys, four dial panels, and the `Default` profile. Review the `DEVICE`,
`PROFILE`, and `LEGACY` constants in `scripts/manage.py` before using it on a
different setup.

## Build and install

Install the font and desktop-command dependencies listed in the [README](../README.md),
then run:

```sh
python scripts/manage.py install
```

The installer:

1. Builds the release executable with Cargo.
2. Copies layouts, renders static icons, and generates the manifest in
   `dist/dev.vincent.deck.sdPlugin/`.
3. Backs up an existing installed bundle to
   `~/.local/state/vincent-deck/plugin-<timestamp>/`.
4. Copies the bundle into OpenDeck's plugin directory and atomically replaces
   the installed executable.

Installation does not restart OpenDeck or change profiles. Close OpenDeck and
wait for its plugin processes to exit, then start `opendeck` again. A running
plugin keeps its previous binary until that restart. Action-definition changes
also need a manifest version bump and an update of placed profile definitions.

The helper scripts `~/.local/bin/deck-workspace` and `deck-theme-cycle` must
already exist; they are not generated by this installer.

## Create a hardware test profile

Close OpenDeck and wait for it to stop. The profile commands reject edits while
an `opendeck` process is running.

```sh
python scripts/manage.py test-profile
opendeck
```

This copies the target Default profile's structure into a new **Vincent Test**
profile and assigns the twelve actions in their default order. It refuses to
overwrite an existing Vincent Test profile. Select that profile in OpenDeck.

Review the Terminal tile and Volume panel first, then all controls:

- Key-down invokes once; key-up is ignored. Agent toggles the scratchpad.
- Volume/mic rotation applies 1% per tick and clamps writes to 0–100%. Externally
  set above-cap values remain visible; mute does not change their percentage.
- Dial press and panel tap perform the same action.
- Workspace shows the focused workspace, occupancy, and active window. Rotation
  retains only the latest pending direction while an invocation runs.
- Theme changes recolor all surfaces, including grayscale accents in monochrome
  themes. Rotation drops repeats while busy; press changes wallpaper.
- Night and Record duplicates share their respective pending gates. Recording
  shows total minutes/seconds through `99:59`, then hours/minutes.
- Lock follows externally triggered lock/unlock state.
- Missing dependencies show stale state; failed commands briefly show `ERROR`.
- Rearranged/duplicate instances behave consistently within their controller type.

The known theme-settling and event-query limitations are in [NOTES.md](../NOTES.md).

## Migrate Default

After hardware acceptance, close OpenDeck and wait for it to stop:

```sh
python scripts/manage.py migrate
opendeck
```

Migration replaces the Default profile's eight key and four dial action
definitions in the documented order, clears old action settings, and preserves
contexts and unrelated profile fields. It is not a general migration of arbitrary
layouts or all profiles.

Before writing, it creates a rollback archive under
`~/.local/state/vincent-deck/backups/<timestamp>/`. Keep the printed path. The
archive contains the original Default profile and the specific legacy files and
directories listed in `LEGACY`, preserving permissions and recording absent
paths. It does not delete legacy plugins or perform cleanup.

For an already deployed profile, the original pre-migration archive is the
rollback point for the legacy setup; a later archive reflects the profile as it
existed at that later time.

## Roll back

Replace `<timestamp>` with the archive you want to restore:

```sh
python scripts/manage.py rollback --backup ~/.local/state/vincent-deck/backups/<timestamp>
```

Rollback validates the archive, stops OpenDeck, restores or removes the listed
paths according to their recorded presence, and launches OpenDeck again. Plugin
installation backups (`plugin-<timestamp>`) are separate bundle snapshots, not
profile rollback archives accepted by this command.

## Verify a restart

```sh
pgrep -ax opendeck
pgrep -ax vincent-deck
```

Look for a new `Registered plugin dev.vincent.deck.sdPlugin` entry in
`~/.local/share/opendeck/logs/opendeck.log`, then check the physical tiles/panels.
Process and registration checks alone do not confirm hardware appearance.
